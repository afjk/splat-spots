# Splat Spots 方針

有志が公開 Spatial Capture のリンクを持ち寄る、非公式のディレクトリ。
実装の判断に迷ったらここに戻る。

## 1. このサイトは何か

- **サイト名: Splat Spots**
- **タグライン: Community-curated directory of publicly shared Insta360
  Spatial Captures. Unofficial and not affiliated with Insta360.**

公式ビューアが WebXR に対応していないこと、公開キャプチャを横断して眺められる場所が
存在しないこと。この2つの欠落が存在理由であり、公式が何を出したとしても、
埋まらない隙間は残る。**撤退の期限は設けない。**
サイト上でも「いずれ不要になるもの」という書き方はしない。

ビューア本体は
[`afjk/insta360-sog-xr-viewer`](https://github.com/afjk/insta360-sog-xr-viewer)。
Splat Spots は**そのビューアへの入口を一箇所に集める**役割。

## 2. 原則

この節が他のすべてに優先する。

1. **Splat Spots は Spatial Capture のホストにならない**
2. **`.sog` / `.ply` / 動画 / 画像を保存・再配布しない**
3. **Insta360 の内部 API を自動利用しない**
4. **Insta360 のサイトを crawler / bot 的に自動取得しない**
5. **公開 Capture の URL はユーザーが投稿する**
6. **投稿は即時公開せず、人間が確認して掲載する**
7. **撮影者・権利者からの削除依頼に速やかに応じる**
8. **Insta360 公式サービスと誤認されない表示にする**

### なぜ内部 API をやめたか

かつては Insta360 の `gs3d/task/detail` を叩いて、公開状態の確認、タイトル・撮影日・
カメラ機種の取得、プレビュー動画の取得を自動で行っていた。技術的には動いたが、
**非公開・非公式のエンドポイントに依存し続けることは、運用の前提にできない。**
先方の都合でいつでも壊れるうえ、bot として他人のサービスを叩き続ける形になる。

代わりに置いたのは**人間の目視確認**である。掲載前に管理者がURLを開く。
自動化より遅いが、前提が壊れない。

将来、公式に利用可能な API が提供されたら再検討する。

## 3. 何を持ち、何を持たないか

| 持つ | 持たない |
|---|---|
| 公開共有リンクとその ID | `.sog` / `.ply` / cameras.json |
| 人が入力したタイトル・タグ・撮影者・出典 | Insta360 由来の画像・動画・その派生物 |
| このサイトが生成したカードのアートワーク | 署名付きアセットURL |

カードに出る絵は、Capture の ID から決定的に生成した点群パターン。
**サイトが自分で描いたもの**であり、Insta360 のコンテンツは一切含まない。
写真がないことを詫びる空箱を置くより、この方がギャラリーとして成立する。

将来、投稿者本人による画像アップロード、明示的に利用可能な画像、公式 API の
thumbnail などが使えるようになったら再検討する。

## 4. アーキテクチャ

```
GitHub Pages ── 公開サイト（Astro / 静的・キャプチャごとに実 HTML）
     ↑ build
GitHub Actions ── push 時にビルドしてデプロイ
     ↑ read
   git: data/captures/*.json ── 公開カタログの「正」
     ↑ 人が確認して手で追加
Cloudflare Worker ── 推薦・削除依頼の受け口
     └ D1 ── 受付箱（未確認の推薦・依頼キュー）
```

### なぜ git が「正」なのか

- **透明性** — 非公式索引だからこそ、何を載せているかが全部見える
- **耐久性** — Cloudflare が使えなくなってもカタログは残り、サイトも生き続ける
- **モデレーション** — 掲載に必ず人の手が入る
- **監査証跡** — 削除依頼 → ファイル削除のコミットが記録として残る

D1 は「受付箱」に徹する。**D1 の内容がそのまま公開されることはない。**

### Worker の責務（これ以外はやらない）

1. URL を parse する
2. 許可された hostname か確認する
3. Spatial Capture URL の形式か確認する
4. Capture ID を抽出する
5. 重複投稿を集約する
6. D1 のキューに保存する

**Insta360 への通信は行わない。** ここが以前との最大の違い。
`POST /api/reports` と、Bearer 認証付きの `GET /api/queue` も持つ。

CORS は既知のオリジンだけをエコーする（任意のオリジンを反射しない）。
フォームにはハニーポット項目があり、埋まっていた場合は保存せず成功を返す。

## 5. データ

`data/captures/<id>.json` を 1 キャプチャ 1 ファイルで持つ。

```jsonc
{
  "id": "GS3DG…",
  "url": "https://app.insta360.com/3dspace/detail/GS3DG…",
  "title": "Example Spot",
  "description": "",
  "author": null,
  "tags": ["architecture"],
  "source_post": null,
  "camera": null,        // 確実に分かる場合のみ
  "captured_at": null,   // 確実に分かる場合のみ
  "submitted_at": "2026-08-23",
  "status": "published"  // published | unlisted
}
```

**API 由来でしか取れなかった項目を必須にしない。** `camera` と `captured_at` は、
ユーザー入力か管理者が確実に知っている場合だけ設定する。推測で埋めない。

`status` は残してあるが、いま自動で書き換えるものは存在しない。
将来 verify を復活させる余地として置いている。

## 6. 掲載の流れ

```
推薦フォーム → D1 キュー → 人が URL を開いて確認 → data/captures/<id>.json → 公開
```

確認するのは次の3点。

- URL が実際に開くか
- Spatial Capture か
- 明らかに不適切な内容ではないか

**投稿された瞬間に公開される仕組みにはしない。**

推薦は誰でもできる。自分が撮ったものでなくてよい。ただし
**すでに一般公開されているもの**に限る、とフォームに明記する。

## 7. 削除

`npm run remove` でレコードを消し、コミットして push すれば掲載から外れる。
Splat Spots はレコードしか持っていないので、**それで削除は完了**する。

サムネイルを持っていた頃は git 履歴に画像が残る問題があったが、
**画像を一切保持しなくなったため、この問題自体が消滅した。**

## 8. デザインの方向

- **ダークキャンバス固定** — `#08080a` 系。ライトテーマは用意しない
- **カードは生成アートワーク** — Capture ID から決定的に描く。同じ Capture は毎回同じ絵
- **カードのメタ** — タイトル / 説明 / 撮影者 / タグ、分かる場合のみ撮影日・カメラ
- **詳細ページ** — ビューアを全幅で上に置き、メタ情報は下のレール
- **継承するもの** — mono 系のアクセント（技術的アーカイブという性格に合う）

キャプチャごとに実 HTML を生成するので個別ページは共有に耐えるが、
**個別の OGP 画像は持たない**（画像を生成・保持しない方針のため）。
共有時はサイト共通の OG 画像になる。

## 9. 公開先

- サイト: `https://afjk.github.io/splat-spots`
- ビューア: `https://afjk.github.io/insta360-sog-xr-viewer/?id=GS3DG…`
- API: `https://splat-spots-api.afjk01.workers.dev`

ビューア URL の組み立ては `src/lib/viewer.ts` の 1 箇所に閉じ込めておく。

## 10. 経緯

このサイトは ChatGPT Sites 上の Next.js アプリとして始まり、次の順で移した。

| | 移したもの | 状態 |
|---|---|---|
| 1 | フロントエンドを Astro + GitHub Pages へ | 完了 |
| 2 | 受付を自分の Cloudflare アカウントの Worker + D1 へ | 完了 |
| 3 | 旧 Next.js 実装の撤去 | 完了 |
| 4 | ChatGPT Sites 版の停止 | 完了（2026-08-23） |
| 5 | Insta360 内部 API への依存の除去 | 完了（2026-08-23） |

移行の動機は2つあった。**見た目**と、**基盤がいつまで使えるか分からないこと**。
後者は「特定の事業者に預けたものは、その事業者の都合で消える」という一般の問題で、
5 の判断（他人の非公開 API に依存し続けない）も同じ理由から来ている。

いま依存しているのは GitHub Pages と Cloudflare Workers + D1 だが、
**公開カタログは git にあるため、どちらが消えてもデータは残る。**

## 11. スコープ外

- 広域クロールや ID 列挙による発見
- Capture 本体や派生画像の保持
- Insta360 の内部 API を用いた自動確認・自動 verify
- 所有者確認を伴う本格的なモデレーション基盤
- ユーザーアカウント、コメント、いいね
- XR Viewer 側の仕様変更（別リポジトリ・別課題）
